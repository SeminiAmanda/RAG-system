## q05
**Question:** How do updated weights reach the vLLM server during asynchronous GRPO training?

**Answer:**
> Updated weights are pushed to the vLLM server after every `weight_sync_steps` training steps. The trainer uses NCCL to transfer the new weights (or, when LoRA is enabled, only the adapter) to the server so that subsequent generations use the latest policy. The sync mode is chosen when the trainer starts, and the server receives the weights via the NCCL‑based weight‑transfer configuration. [2]

**Passages cited**:
### [2] trl/async_grpo_trainer.md | Asynchronous GRPO > How it differs from [`GRPOTrainer`]
```text
Tools and environment methods can be synchronous or asynchronous. Synchronous tools run on a thread pool sized to `max_inflight_tasks`, so a slow tool never blocks the other in-flight vLLM requests. Within one assistant turn, tool calls run in the order the model emitted them. Up to `max_inflight_tasks` synchronous tools therefore run at once, so a tool that reads or writes shared state must be thread-safe.

After every `weight_sync_steps` training steps, the updated weights are transferred to the vLLM server via NCCL so that subsequent generations reflect the latest policy.

Because generation and training run concurrently, the training samples may have been generated by a slightly older version of the model. The `max_staleness` parameter controls how many weight updates a sample can lag behind before being discarded.
```

## q35
**Question:** How does GRPOTrainer run several async reward functions, and when is that useful?

**Answer:**
> GRPOTrainer runs multiple async reward functions concurrently (via `asyncio.gather`), so their latency overlaps rather than being sequential. This is useful when a reward depends on slow I/O operations—e.g., calling a remote service or database lookup—because it keeps the training loop from waiting on each reward call one after another. [1][3]

**Passages cited**:
### [1] trl/grpo_trainer.md | GRPO Trainer > Customization > Using a custom reward function > Example 5: Asynchronous reward functions
```text
Custom reward functions can also be defined as `async def` coroutines. This is useful if your reward depends on slow I/O (for example, calling a remote service). When you pass multiple async reward functions, [`GRPOTrainer`] executes them concurrently so their latency overlaps.

Below is a minimal example of an async reward function that simulates an I/O-bound operation:

```python
import asyncio

async def async_reward_func(prompts, completions, **kwargs):
    # Simulate an I/O-bound call (e.g., HTTP request, database lookup)
    await asyncio.sleep(0.01)
    # Simple toy reward: 1.0 if the completion is non-empty, else 0.0
    return [1.0 if completion else 0.0 for completion in completions]
```
```

> The Transformers exporters expose one class per runtime, e.g.:
> 
> - `DynamoExporter` → any PyTorch runtime (AOT, TorchScript, etc.)  
> - `OnnxExporter` → any ONNX runtime (ORT, TensorRT, OpenVINO)  
> - `ExecutorchExporter` → ExecuTorch (mobile/edge)  
> - `OpenVINOExporter` → OpenVINO runtime  
> 
> So to switch runtimes, simply instantiate the desired exporter instead of the one you used before.  
> For example:
> 
> ```python
> from transformers.exporters import OnnxExporter, ExecutorchExporter
> 
> # ONNX
> exporter = OnnxExporter()
> # ExecuTorch
> exporter = ExecutorchExporter()
> ```

**Question:** How can I use Dataset.map to generate extra versions of a sentence with a fill-mask model?

**Answer:**
> Use `Dataset.map` to apply a custom function that masks a word, runs a fill‑mask pipeline, and returns the original sentence together with the generated variants.  
> The function must accept a dictionary of examples and return a dictionary that will be added to the dataset.
> 
> ```py
> from random import randint
> from transformers import pipeline
> 
> # 1. Load a fill‑mask pipeline (e.g., RoBERTa)
> fillmask = pipeline("fill-mask", model="roberta-base")
> mask_token = fillmask.tokenizer.mask_token
> 
> # 2. Define the augmentation function
> def augment_data(examples):
>     outputs = []
>     for sentence in examples["sentence1"]:          # or any text column
>         words = sentence.split()
>         # pick a random word to mask
>         K = randint(1, len(words)-1)
>         masked_sentence = " ".join(words[:K] + [mask_token] + words[K+1:])
>         # get predictions
>         predictions = fillmask(masked_sentence)
>         # keep the original sentence + top 2 predictions
>         augmented_sequences = [pred["sequence"] for pred in predictions[:2]]
>         outputs += [sentence] + augmented_sequences
>     return {"data": outputs}                       # new column with all versions
> 
> # 3. Apply the function to the whole dataset
> augmented_dataset = dataset.map(augment_data, batched=False)
> ```
> 
> The resulting `augmented_dataset` will contain a new column `data` that holds the original sentence and the extra sentences produced by the fill‑mask model. This demonstrates how `Dataset.map` can be used for data augmentation with a fill‑mask model. [1]
